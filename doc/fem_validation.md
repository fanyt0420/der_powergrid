# 两个完整 DER 算例的验证结果

验证日期：2026-10-17。测试对象为仓库已有 `ieee13_unbalanced_der` 和 `ieee13_measured`，直接使用它们的网络、负荷和 DER 曲线，没有用新造的网络替换这两个验收算例。设备包含缺相线路、源阻抗、变压器、自动调压器、电容器、delta/wye 和多种负荷模型、PV、风电、储能、EV。

## 运行范围

| 数据集 | 时间步 | 时间间隔 | 相节点 | 支路 | DER |
|---|---:|---:|---:|---:|---:|
| ieee13_unbalanced_der | 24 | 1 h | 41 | 17 | 13 |
| ieee13_measured | 96 | 15 min | 41 | 17 | 13 |

两个算例均可通过 `python run.py --data-dir data/<算例名> --solver fem` 跑完，自动调压和 Volt–Var 均开启，储能 SOC 由原时序框架推进。节点数包含 SourceBus 三相，因此与旧版仅从 650 节点边界向下游求解的 38 个相节点不同。

验收还通过子进程禁止导入 `dss` 再运行上述两条命令，证明原生后端没有调用 OpenDSS 生成边界值、导纳、抽头或电压结果。

## 结果：各自运行自动控制

以下比较两个生产后端各自输出的全时段结果。

| 全时段最大差异 | unbalanced_der | measured |
|---|---:|---:|
| 电压幅值差（pu） | 0.0124962 | 0.0131766 |
| 复电压差（pu） | 0.0124962 | 0.0132225 |
| 支路首端最大电流幅值差（A） | 3.2173 | 3.3822 |
| 调压器档位差 | 2 档 | 2 档 |
| 有功线路/变压器损耗差（kW） | 0.1962 | 0.4546 |
| BESS SOC 差（百分点） | 0 | 0 |
| FEM 自身最大 KCL 残差（A） | 4.31e-7 | 5.33e-7 |

自动控制下约 1.25%–1.32% 的最大电压差必须与结果一并报告。两种实现的初始抽头、死区内选择和控制步进过程不同；不能将这些差异说成“有限元方程的数值精度”。当前回归接受这一级的自动控制差异，但还不能用于要求控制动作逐步等同 OpenDSS 的研究。

## 结果：相同抽头与 DER 指令

在每个时刻重放 OpenDSS 的最终抽头、最终 DER P/Q，FEM 使用自己的矩阵和迭代重新求解。这一诊断用于隔离控制状态差异，不是 FEM 生产运行必须依赖参考解。

| 全时段最大差异 | unbalanced_der | measured |
|---|---:|---:|
| 电压幅值差（pu） | 0.00010563 | 0.00012807 |
| 复电压差（pu） | 0.00012246 | 0.00014458 |
| 支路首端最大电流幅值差（A） | 0.3433 | 0.4042 |
| 有功线路/变压器损耗差（kW） | 0.0990 | 0.1170 |

这是两个实现间的差异，不是真实电网测量误差。剩余差异也不全是迭代容差：JSON 中开关采用明确的总阻抗，而 DSS 原文件采用带长度的 Line 开关；部分线路在 DSS 侧存在默认充电参数；原生储能的端口近似没有完整复刻 OpenDSS Storage 状态机。对照保留两套原有输入，并没有为了降低误差而修改数据。

## 测试与复现

```powershell
python -m unittest discover -s test -v
python -m test.compare_solvers --output output/fem_comparison
```

9 项测试通过，覆盖：两个完整时序、双后端对照、禁止导入 DSS 的统一 CLI、三角形电流守恒、源短路容量换算、变压器相移/变比、储能功率符号/空闲耗电、短线路 QSTS 与长度单位。CLI 测试同时核对六类输出、抽头/SOC 范围、路径交点电压一致性。

完整比较器会输出：

- `voltage_comparison.csv`：按时间/母线/相匹配的电压。
- `branch_comparison.csv`：按时间/支路匹配的电流、功率与抽头。
- `system_comparison.csv`：损耗、控制迭代、DER 指令、SOC、约束结果。
- `matched_control_comparison.csv`：每一步相同控制条件下的最大差异。
- `summary.json` 和总 `report.json`：统计、输入 SHA-256、环境版本、计时。

本次归档的机器可读证据见 [validation/fem_comparison_2026-10-17.json](validation/fem_comparison_2026-10-17.json)。环境为 Python 3.10.11、NumPy 2.2.6、SciPy 1.15.3、pandas 2.3.3、dss-python 0.15.7。

## 当前成果与限制

目前已经完成从“简单线路后端 + 单独的固定配置 IEEE13 脚本”到“统一入口下的完整 DER 时序原生求解器”的扩展。输入数据、SOC 推进、约束评估、输出结构都复用了原有框架，提供了可重复的物理检查和双层对照。

同一台机器单次记录的 QSTS 用时约为：24 步 OpenDSS 0.079 s、FEM 0.635 s；96 步 OpenDSS 0.326 s、FEM 2.312 s。该计时只覆盖内存中的 QSTS 计算，不含 CSV 读取/输出，build 时间另存；这只是本机运行记录，不是充分的性能实验。目前没有速度优势结论，记录中原生 Python 实现更慢。

下一阶段若关注性能，需要重复运行、预热、报告分布，并在相同设备模型/控制条件及精度要求下增加大规模馈线；若关注 DER 资源分配，还需要在此潮流后端上建立优化问题。本次实现的是潮流求解与现有控制，不是资源分配优化器。
