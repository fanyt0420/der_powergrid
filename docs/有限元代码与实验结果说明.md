## 2. 求解器的计算含义

`build()` 先根据母线和相别建立相节点索引。每条线路使用三相复阻抗矩阵 `Z_e`；在该段上选取两端点的分片线性 P1 基函数，得到单元矩阵 `[[Y_e,-Y_e],[-Y_e,Y_e]]`，其中 `Y_e=Z_e^{-1}`。所有线路装配成稀疏矩阵，对电源三相节点指定固定电压，对非电源节点的 PQ 注入求解非线性 KCL。稀疏矩阵只分解一次，每个时刻复用分解；上一时刻的电压作为下一时刻初值。

`solve()` 把负荷、PV、风电和 EV 转换为各相复功率注入，进行电流注入不动点迭代 `I=conj(S/V)`；PV 的 Volt-VAR 控制通过外层迭代更新无功。最终生成母线电压、线路电流与功率、损耗、源功率、迭代次数和下一时刻热启动状态。线路间的互阻抗会耦合三相；单相设备接入造成不平衡。

这里的 P1 图有限元在**每段系数常数且忽略线路并联电纳**时，装配结果与串联线路节点导纳矩阵相同。它目前是可验证的原型，尚没有通过减少自由度获得有限元意义上的加速。实验测得的时间差不能作为普遍性能优势。

## 3. 用了什么数据

实验脚本在运行时生成数据，不依赖机器上的 IEEE 13 文件路径。默认设置为：

- 60 段串联的三相径向馈线，每段 0.12 km，总长 7.2 km；三相线路阻抗矩阵含非零互阻抗，线路并联电容设为零。
- 共 61 个三相母线，即 183 个相节点；每段末端各接 A/B/C 相负荷，共 180 个单相星形 PQ 负荷。各相负荷系数不同，且负荷随时刻变化。
- 沿线每 3 段接入单相 PV，共 20 个；每 8 段接入单相 EV，共 7 个，总计 27 个 DER。PV 有日内出力和 Volt-VAR 控制，EV 有充电时段变化。
- 仿真从 2026-01-01 00:00 开始，每小时一个工作点，共 24 个时刻。OpenDSS 电源设为极小非零内阻；有限元电源为理想固定电压。因此电源功率会有很小的模型差异。

输入保存在运行时生成的 `work/fem_radial_case/`，其中 `network.json` 和 `network.dss` 描述同一个受限网络，CSV 文件给出负荷及 DER 的逐时刻出力。这是**合成验证算例**，不是项目现有完整 IEEE 13 节点算例，也不代表真实馈线测量数据。

## 4. 得到什么结果

在 Intel Core i7-14650HX（16 核、24 逻辑处理器）上，默认算例一次运行的结果为：

| 指标 | 结果 |
|---|---:|
| 最大电压幅值差（有限元对 OpenDSS） | `3.59995e-10 pu` |
| 平均电压幅值差 | `2.77821e-10 pu` |
| 最大总损耗差 | `6.60505e-11 kW` |
| 最大电源有功差 | `1.99605e-4 kW` |
| 有限元模型构建 | `0.00283 s` |
| OpenDSS 模型构建 | `0.01077 s` |
| 有限元 24 时刻 QSTS | `0.09887 s` |
| OpenDSS 24 时刻 QSTS | `0.13016 s` |

这些是**一次本机运行**的耗时，未做重复统计，也未包含结果 CSV 写盘。电压和损耗的高度一致，验证的是两个程序在这个简化网络上求解了相同的串联线路模型；不能外推到完整 IEEE 13、不同计算机或大规模真实系统。机器生成的精确数值写在 `output/fem_radial_experiment/summary.json`，逐节点电压比较写在 `voltage_comparison.csv`；两者为可再生文件，未纳入 Git。

## 5. 怎样复现

在仓库根目录运行：

```powershell
python -m pip install -r requirements.txt
python experiments/fem_radial_experiment.py --segments 60 --hours 24
```

也可在实验生成后通过现有 QSTS 入口运行有限元求解器：

```powershell
python run.py --data-dir work/fem_radial_case --solver fem
```

不带 `--solver` 时仍使用 OpenDSS。完整 IEEE 13 算例中有变压器、调压器、开关、并联电容、不同接线方式等，本原型目前会明确拒绝不支持的元件，不能用于该算例的正式结论。下一步应先补齐这些模型并逐项对照，再研究跨多段线路的粗化、自适应基函数与误差—耗时曲线。
